`findings.json` must be a JSON array. Use `[]` when there are no findings. Each finding object must include non-empty string fields `id`, `title`, `status`, `severity_guess`, `confidence`, and `summary`. Every finding's `severity_guess` must be exactly `High`, `Medium`, or `Low`, including findings that are or may become non-production records. `schema_version` is optional; omit it, or set it to `"1.0"` or `"ultrafuzz.finding.v1"`. `status` must be a non-empty lifecycle string. Prefer canonical values such as `candidate`, `needs-review`, `duplicate`, `false-positive`, `confirmed`, `fixed`, or `wont-fix` when they fit. If you include `triage_classification`, use one of `true-positive`, `false-positive`, `undetermined`, `incomplete-spec`, `harness-defect`, `repair-candidate`, `spec-gated`, or `defensive-hardening`. Use `severity_guess`; do not use `severity` as a replacement. If you include `evidence`, each entry may be a non-empty string reference or an object with optional non-empty string `kind` and `path` fields plus any other useful metadata. Object `path` fields must be safe relative file paths without anchors or line selectors. Put a section anchor in `fragment`, one source span in positive integer `line` and optional `end_line`, and disjoint spans in `line_ranges`, an array of at least two objects such as `[{"line":105,"end_line":107},{"line":154,"end_line":185}]`; every `end_line` must be no smaller than its `line`. Never emit a one-entry `line_ranges`, and never combine `line_ranges` with `line` or `end_line`. Keep independent explanatory prose in `detail`; never embed selectors into `path` or replace prose with them.
