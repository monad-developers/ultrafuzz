`findings.json` must be a JSON array. Use `[]` when there are no findings. Each finding object must include non-empty string fields `schema_version`, `id`, `title`, `status`, `severity_guess`, `confidence`, and `summary`. Use `schema_version: "1.0"`. `status` must be a non-empty lifecycle string. Prefer canonical values such as `candidate`, `needs-review`, `duplicate`, `false-positive`, `confirmed`, `fixed`, or `wont-fix` when they fit. If you include `triage_classification`, use one of `true-positive`, `false-positive`, `undetermined`, `incomplete-spec`, `harness-defect`, `repair-candidate`, `spec-gated`, or `defensive-hardening`. Use `severity_guess`; do not use `severity` as a replacement. If you include `evidence`, each entry may be a non-empty string reference or an object with optional non-empty string `kind` and `path` fields plus any other useful metadata. Object `path` fields use safe relative file paths such as `src/Contract.sol` or `README.md`. Put single-line anchors in `line`, section anchors in `fragment`, and line ranges in `detail`.
