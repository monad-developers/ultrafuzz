`findings.json` must be a JSON array. Use `[]` when there are no findings. Each finding object must include non-empty string fields `id`, `title`, `status`, `severity_guess`, `confidence`, and `summary`. `schema_version` is optional; omit it, or set it to `"1.0"` or `"ultrafuzz.finding.v1"`. `status` must be a non-empty lifecycle string. Prefer canonical values such as `candidate`, `needs-review`, `duplicate`, `false-positive`, `confirmed`, `fixed`, or `wont-fix` when they fit. If you include `triage_classification`, use one of `true-positive`, `false-positive`, `undetermined`, `incomplete-spec`, `harness-defect`, `repair-candidate`, `spec-gated`, or `defensive-hardening`. Use `severity_guess`; do not use `severity` as a replacement. If you include `evidence`, each entry may be a non-empty string reference or an object with optional non-empty string `kind` and `path` fields plus any other useful metadata. Object `path` fields must be safe relative file paths without anchors or line selectors; put section anchors in a separate `fragment` or `detail` field.
