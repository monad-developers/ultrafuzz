## Generated-test Bundle Instructions

This node declares an `ultrafuzz/generated-tests@3` transport contract. The role-specific prompt controls whether executable evidence is required for this node. Unless that prompt expressly requires executable evidence, generated test, PoC, fuzz-test, and support files are optional. The manifest is always mandatory: write it to exactly {{generated_tests_manifest_path}} and validate it even when it describes an empty bundle.

When you author executable evidence, keep runnable generated test or reproducer source under {{strategy_attempt_test_dir}} and mirror every declared bundle file under {{generated_tests_dir}}. Do not invent executable files merely to populate the manifest. When no runnable test or reproducer was authored, use the empty bundle defined by the schema; an empty bundle is valid evidence transport and is not a reason to block, demote, or invalidate an otherwise adequately supported finding.

Read the exact pinned schema named by `Validate against` in the central Ultrafuzz Output Contract and run the exact `Validation command`, `Contract validation command`, and `Task-context validation command` rendered beside it. The task-context command checks companion files plus the runtime-owned run and logical-producer identity; correct any mismatch before returning. The schema alone owns the manifest's JSON version, field names, types, required and optional members, and empty form.

Bind `run_id` exactly to {{run_id}} and `node_id` exactly to {{logical_node_id}}. The node identity is the logical producer shown here, not a concrete attempt, loop, or model-fanout identity. Bind the bundle framework to the one checked-in native framework used by the whole atomic bundle. Never mix frameworks in one bundle or assign a separate framework to an individual companion. These run, producer, and repository-context bindings are checked beyond JSON Schema.

Classify only independently runnable tests and reproducers as generated tests. Classify imported helper libraries, mocks, fixtures, deployment scripts, text data fixtures, and other non-runnable dependencies as support files. Every declared companion, including data fixtures, must be strict UTF-8 text rather than binary data and must live beneath the artifact bundle, never at a workspace path. When the bundle is empty, still bind its framework to the checked-in native framework. Before returning, validate after every declared companion is present, singly linked, regular, non-empty, and neither a symlink nor reachable through one.
