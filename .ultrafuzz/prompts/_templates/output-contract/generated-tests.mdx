## Generated-test Bundle Instructions

This node is a generated-test producer. Author runnable generated test source files under {{strategy_attempt_test_dir}}, mirror every declared bundle file under {{generated_tests_dir}}, and write the manifest to exactly {{generated_tests_manifest_path}}.

The manifest must be a closed JSON object with `schema_version` exactly {{generated_tests_schema_version}}, `run_id` exactly {{run_id}}, `node_id` exactly {{logical_node_id}}, and the `generated_tests` and `support_files` arrays. The `node_id` is the logical producer identity shown here, not a concrete attempt, loop, or model-fanout identity.

Put only independently runnable test/reproducer files in `generated_tests`. Put imported helper libraries, mocks, fixtures, deployment scripts, text data fixtures, and other non-runnable dependencies in `support_files`; never misclassify them as runnable tests. Every test and support companion, including data fixtures, must be strict UTF-8 text; binary files are not supported. Both arrays use the same closed entry shape: required artifact-relative `path` under `generated-tests/<relative-file>`, exact positive `size_bytes`, and exact lowercase `sha256`; optional fields are `language`, `framework`, `description`, and documented closed `provenance`. Do not put workspace paths in either manifest array.

Entries must be unique within each array. Paths must be unique across both arrays, and no file path may be the slash-delimited prefix of another path. A non-empty `support_files` array requires at least one `generated_tests` entry. Use both arrays empty when no runnable test was produced. Before returning, validate the final manifest with the exact validation command in the output contract after every declared companion is present, regular, non-empty, and not a symlink.
