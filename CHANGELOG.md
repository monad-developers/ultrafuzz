# Changelog

## Unreleased

### Breaking changes

- **[config] [docs] [evals]** Removes the `full` audit profile and renames its packaged topology to `topologies/exhaustive.yml` (byte-identical, topology digest unchanged); the `exhaustive` profile now runs that complete specialist workflow at its existing maximum settings, and no longer follows an edited `.ultrafuzz/topology.yml` (a project `topology_path` or `--topology-path` still overrides it). Configurations that select `full` now fail with the standard unknown-profile diagnostic. The public `full` and `threat-model` benchmark lanes launch with the `exhaustive` profile; the only effective policy change on those lanes is `same_agent_attempts` 3 → 5, since lane and target pins outrank the remaining profile settings (#792).
- **[config] [docs]** Renames the unmodified built-in audit profile from `balanced` to `default` and removes the separate default pointer. Configurations that select `balanced` now fail with the standard unknown-profile diagnostic and must select `default` or omit `audit_profile`. Historical run metadata retains its exact recorded id; eval-history and benchmark reporting do not key cohorts by audit-profile id, so otherwise matching runs remain in the same reporting cohort across the migration boundary (#534).
- **[config] [docs]** Consolidates maximum-effort audits under `exhaustive` by removing the overlapping `thorough` profile, and removes the transitional `fuzz-only` profile and topology used for v0.x/v0.1 comparisons. Configurations that select either removed profile now fail with the standard unknown-profile diagnostic; select `exhaustive` for maximum built-in breadth and depth, while focused stateful-invariant campaigns continue to use `invariant-only` (#648).
- **[config] [docs] [modal] [evmbench]** Removes the dead `run.max_parallel_nodes` key and its `ULTRAFUZZ_MAX_PARALLEL_NODES` environment override. The key was parsed, defaulted, schema-validated, documented, and set by four audit profiles, but no runtime code ever read it, so raising it never widened throughput; `run.max_parallel_agents` is now the only concurrency limit in the contract, and it bounds every task the workflow submits rather than only agent tasks. There is no deprecation shim: the loader is strict about unknown keys, so an `ultrafuzz.toml` that still sets `max_parallel_nodes` fails to load with a `CONFIG_UNKNOWN_FIELD` error naming `run.max_parallel_nodes` — delete the line. `ULTRAFUZZ_MAX_PARALLEL_NODES` is instead silently ignored, since environment variables are not subject to the unknown-key check. `maxParallelNodes` and `max_parallel_nodes` are also gone from the sealed resolved-config schema, `required` lists included, so a `config.resolved.toml` sealed by an older build no longer re-validates on a newer one; the schema version stays `resolved-config.v3`. Generated Modal workspace configs and the evmbench adapter stop emitting the key, and the adapter's benchmark concurrency still lands on `max_parallel_agents` exactly as before (#933).

### Other changes

- Excludes tracked submodule gitlinks from workspace-patch staging. Task workspaces are linked worktrees, where a submodule's inherited `gitdir: ../../.git/modules/<path>` pointer resolves to nothing, so naming the gitlink in the staging `git add` aborted the whole invocation with `fatal: not a git repository` and killed the capture. Since a Foundry target has submodules by definition, this failed 6 of 63 verify lanes in one run and, through a lane that was not `continueOnFail`, ended a 13-hour run at 93% completion. Gitlinks are selected by mode rather than by path, so a submodule outside `lib/` is covered too; a submodule revision change could never have reached an applicable patch in any case, because `validateWorkspacePatchCapture` rejects a `160000` mode outright (#910).
- Pi JSON event streams now use the interpreter-first stream format inside Smithers, and a successful tool-only terminal assistant message produces a transport-owned summary. Structured agent tasks no longer parse an unrelated earlier tool payload from the intact NDJSON transcript when the model emits no terminal text (#927).
- Generated artifact-aware agent facades now preserve Smithers' CLI continuation discriminator, file-change parser, and checkpoint production/consumption declarations, so same-attempt output correction resumes the exact captured agent session instead of cold-starting behind the wrapper (#929).
- Controller lifecycle evidence now authenticates the complete sealed execution-snapshot contents once per process-private capability, then preserves every command's fail-closed boundary with descriptor-held path identity, exact directory/link checks, and nanosecond inode change tokens. Synchronization and controller re-finalization no longer reread the full protected payload for every terminal-attempt inspection, while reloaded evidence and same-size writes still require or invalidate a full byte attestation (#904).
- Explicit controller refreshes now source current stock `@ultrafuzz/*` module bytes from the package closure executing the refresh instead of the installation recorded by the launch seal. Compatible fixes installed in another worktree can therefore produce a distinct authenticated controller generation, while sealed manifests, dependency and executable authority, schemas, campaign inputs, and absent synthetic or retired modules remain rooted in the original authority (#911).
- Authenticated controller refreshes now source stock adapter bytes directly from the installed package closure, so a run created before an adapter update can rotate to the current controller without rewriting its project scaffold. Strict project adapter validation remains unchanged for new runs, and mutable project adapter bytes are never admitted into the refreshed execution generation (#902).
- Explicit failed-task recovery now maps a failed zero-retry artifact verifier back to its finished agent-owned artifact producer and resets the producer's dependent closure. `resume --retry-failed` can therefore regenerate missing or malformed model outputs instead of replaying the verifier against the same stale artifact directory (#925).
- Seals the trusted validator CLI and its complete transitive package graph into a run-owned content-addressed closure with confined ESM/CommonJS resolution and sanitized Node loader search. Ordinary source rebuilds cannot change an active task identity; controller refreshes source workspace packages from the authenticated launch generation, verify the historical schema/build contract before publishing or selecting a rotation, and recover legacy launcher migration through fail-closed authenticated rotation evidence (#897).
- Routes Codex API-key preflight through the selected custom provider, honors `config_dir` in API-key mode, and forwards the configured credential variable to the spawned CLI. The configured route overrides ambient endpoints, and OpenRouter credentials are validated against its authenticated key endpoint before a real model request (#642).
- Prepares the v0.1.0 source-release package set without claiming an npm publication: every workspace manifest declares version `0.1.0`, remains `private`, carries repository metadata, and preserves the documented Node.js 22.19+ floor. CI and release validation now reconcile the filesystem, root, pnpm, and pack inventories for all 12 packages, install their tarballs into a clean consumer, compare every installed allowlisted payload byte-for-byte, and exercise the installed `ultrafuzz init` and `validate` commands. The packaged topology set matches the shipped profile lineup: the editable project default plus the separately packaged `exhaustive`, `invariant-only`, and `smoke` topologies.
- Isolates authenticated pinned-reference Git operations from ambient repository, global, and system configuration: inherited Git and raw Ultrafuzz credential variables are removed, credential helpers and prompts are disabled, an exact-remote authorization header is scoped to the allowlisted repository, and `ls-remote` runs outside the caller's repository. The same sanitized context covers filtered-clone lazy blob and tree reads, and failures redact both the raw token and its derived Basic value.
- Makes finding and final-report provenance tier-aware: producer ancestry, dedupe roots, source finding IDs, and family IDs must resolve to known upstream identities and agree with every stronger claim. Newly minted finding and family IDs remain valid, while contradictory, unknown, or unmatched forged source claims fail before report publication.
- Updates the release-only Web3 vulnerability-database pin to immutable v0.0.2, expanding the planner corpus to 68 capabilities and 141 classes. The reference boundary remains backward-compatible with schema-v1 Markdown pins while validating schema-v3 YAML records, replacement capability identities, optional protocol types, and all five typed detection-step variants; planner guidance retains `detection.strategy`, and selected snapshots preserve the exact structured YAML (#440).
- Reconciles benchmark dispatch after the main-to-release sync around one `benchmark_lane` choice: dispatched smoke runs retain their provider/model/reasoning controls and provider credentials, full retains its four-provider matrix, and threat-model remains pinned to the checked-in OpenAI GPT-5.6 Luna/high profile regardless of form values. Exact-run artifacts still determine longitudinal eligibility, where threat-model remains excluded (#183, #413).
- Makes the opt-in threat-model benchmark a structural gate after its artifacts are preserved: all three canonical targets must retain the threat model, goal plan, and vulnerability-database evidence; the planner-owned expected child count must match independently observed fanout; dynamic children need lineage; and every goal lane must finish successfully. Quality, cost, retries, tokens, and wall-clock remain review telemetry, and nothing dispatches the paid lane automatically (#183).
- Fixes the v0.1.0 threat-model benchmark fixture for the post-#373 goal-plan cardinality fields and removes an inert reporter-upload declaration; public bundle retention is unchanged (#183).
- Adds the `threat-model` benchmark lane: the v0.1.0 release gate that runs the production topology against the three pinned Ultrafuzz-bench targets. The smoke lane substitutes the reduced `packages/config/topologies/smoke.yml` graph and the full lane is bound to the EVMBench cohort, so before this lane the `threat-model`, `goal-plan`, `threat-goals`, and `class-goals` nodes never met a real pinned protocol. The lane prunes nothing, takes its GPT-5.6 Luna/high runner from `benchmarks/lanes.json` rather than the dispatch form, retains `THREAT_MODEL.md`, `threat-model.json`, `goal-plan.json`, and `vulnerability-db-manifest.json` from every row, and is refused by the history publisher so its different execution policy never joins the longitudinal series. Select it with the `benchmark_lane` workflow-dispatch input; nothing dispatches it automatically (#183).
- `goal-plan.json` now records its own dynamic-fanout expectation at planning time: `expected_child_count`, `threat_count`, `applicable_class_count`, `max_dynamic_nodes`, and `goal_lanes`, each lane naming the node IDs it owns. The cardinality rule — one dynamic child per modeled threat plus one per applicable class, with the fixed roaming node as a static lane rather than a child — is computed by exactly one function, which the recorder, the contract, and the pre-existing `counts` block all check against; `threat_count`, `applicable_class_count`, and `expected_child_count` are therefore aliases of `counts.threats`, `counts.applicable_classes`, and `counts.dynamic_goals` that cannot drift from them, and `max_dynamic_nodes` and `goal_lanes` are the new information. A lane is one goal rather than one dynamic group, so per-goal cost and per-goal failure are visible and group totals stay derivable by summing a `kind`. A plan that misstates its own cardinality, or expects more children than `run.max_dynamic_nodes` permits, fails as a plan instead of aborting the expansion later. `evalRunExpansion` reads those numbers and reports `expected_vs_actual` and per-lane failures, tokens, cost, and wall-clock; it never recomputes the rule, so a planner that under-expands is caught by a component that did not compute the expectation. Dynamic child node states now carry `provenance.source_node_id`, the lineage key both sides agree on (#364, #183).
- Usage ledger entries gain an optional `node_id`, the identity `state.json` keys a node under, and per-node or per-lane cost is joined on it. `attempt_id` could not serve: it is a digest of the workflow run, node, iteration, and attempt, so no reader can join to it without copying the hash rule. The field is optional because `usage.jsonl` is durable — ledgers written before it existed still parse — and a run resumed across the upgrade does not fail its replay when a recorded entry gains the key. An entry with no `node_id`, or one naming a node a lane never ran, is reported as `unavailable` with a reason rather than as a zero-cost lane (#364, #183).
- Adds first-class dynamic runtime nodes to topology v2. A static node can expand a schema-validated array from a completed upstream node into independently scheduled children with deterministic IDs such as `dynamic:threat:liquidation:overdue`. Children are ordinary nodes: visible, durable, independently retryable, bound by the existing global concurrency limit, and attributable in findings. The first successful expansion persists a manifest, so resume and controller takeover reuse it rather than re-evaluating changed planner output. A configurable `run.max_dynamic_nodes` (env `ULTRAFUZZ_MAX_DYNAMIC_NODES`) fails an oversized expansion explicitly instead of truncating it (#179).
- Adds threat modeling and additive `/goal` discovery to the default topology. A `threat-model` node produces `THREAT_MODEL.md` and canonical `threat-model.json` from actor/flow evidence, `goal-plan` turns that plus the pinned vulnerability database into schema-validated `goal-plan.json`, and the runtime expands one goal per threat and one per applicable vulnerability class alongside a fixed roaming goal that is an ordinary static node. Findings, deduplication, reports, and inspection carry the producing node ID (#182).
- Integrates the pinned external Web3 vulnerability database as a dedicated `kind: vulnerability-database` reference. Ultrafuzz fetches the exact immutable commit through the existing digest-checked reference cache, validates the upstream catalog, capability registry, and class records before planning, records repository/commit/schema/aggregate provenance in `vulnerability-db-manifest.json`, and copies only the exact selected source records into the report bundle. The shipped pin is public and materializes without any credential (relates to #180).
- Adds a validated controller-to-worker selected-task handoff so a Modal node worker executes only the attempt its controller materialized, and refuses a handoff that does not reproduce the canonical task identity. Runtime dependency extensions retain exact compile-time-derived verifier requirements, including agentic empty-group fallbacks, and relocated workers reconstruct generated single- and multi-model dependency output contracts from compiled templates without rematerializing controller-owned expansion state (#179, #182).
- `eval status` now names active and waiting nodes, preserves their wait reason and next eligible action in JSON, and shows whether the linked workflow is running or stopped, so controller-loss stalls identify the exact takeover work instead of appearing only as stale checkpoints (#497).
- Fail workflow launch before run creation when an active topology's required campaign executables are unavailable, expose those requirements through `ultrafuzz doctor`, and probe cloud requirements inside the configured provider image (#498).

- Hydrated pinned submodules now use exact per-task Git worktree configuration, so Foundry and recursive submodule initialization remain offline and cannot contaminate the shared repository configuration or create child Git metadata (#492).
- Adds `ultrafuzz json validate` and producer-side prompt commands backed by one pinned Draft 2020-12 schema bundle; all JSON handoffs now use closed versioned contracts, invalid output fails without host repair or retry, and retained runtime documents are validated before publication (#439).
- Final-review tasks derive current property implementation coverage from the verified catalog, current implemented-properties handoff, and resolved priority configuration whenever the selected topology declares that producer; JSON, findings, and Markdown share one deterministic projector, complete declared report sets remain byte-identical, both CommonMark fence markers exclude proof code from prose-only presentation rules without exempting secrets or private paths, and malformed or non-authoritative inputs fail closed (#460, #461, #464, #465, #470, #471).
- Successful workflow attempts now remain unrecorded during bounded artifact finalization until their canonical output manifest is durable, instead of becoming immutable phantom `failed / artifact-validation` rows in the node-attempt ledger (#352).
- Release-gate checks against the real Kimi Code command surface now retry one transient cold-runner spawn failure and use a bounded 15-second attempt window, while reporting a distinct startup error if both attempts fail (#355).
- Pinned source materialization now rewrites GitHub SCP-style and `ssh://` submodule URLs to public HTTPS through invocation-scoped Git configuration inherited by recursive updates, so public targets hydrate without SSH credentials while retaining exact gitlink pins, checkout isolation, and unchanged behavior for other hosts (#458).
- Pinned local workflows now seal the exact committed bytes, modes, and recursive commit/tree identities of hydrated submodules before removing child Git metadata, restore every fresh or retried task worktree transactionally from the authenticated execution snapshot, and verify the dependency tree again after model work without retaining remotes, submodule network configuration, or URL rewrites (#469).
- The Aave v4 private benchmark ground truth now binds its 12 scored labels to the exact ScFuzzBench fork and immutable revision that contains the injected harness, with regression coverage against the checked-in document (#453; related to #404).
- Retry artifact cleanup now preserves only task-owned prompts directly under the task artifact root, so sealed snapshot prompts remain outside cleanup; finding evidence must already use exact non-empty scalar or typed span metadata without conversion; and Modal launch-state inspection resolves states that carry image IDs through the persisted immutable ID rather than a mutable published name (#416, #443, #444, #449, #450, #451, #452, #455).
- Detached Smithers engines now replace controller-owned execution-snapshot paths with process-owned descriptor paths before admission, so later renders cannot follow a closed or reused `/proc/<pid>/fd/<n>` after the submitting controller exits (#413).
- Workflow submissions and lifecycle inspections now execute from a sealed, content-addressed snapshot of workflow controls and their dependency closure, with immutable generation binding and controller-only capabilities withheld from model subprocesses (#165, #413).
- Runs created before sealed controls and authenticated workflow-link journals keep their stored artifacts, but lifecycle and live-inspection commands now fail closed and require a new run ID instead of synthesizing historical trust. Outside the authenticated one-way 0.32-to-0.34 cutover above, `ultrafuzz init` preserves every existing agent adapter unless the operator explicitly passes `--force`, and preserved outdated adapters receive manual update guidance (#165, #413, #569).
- Hardened workflow execution now requires a Linux host with procfs mounted so the controller and Modal worker can invoke Smithers through held `/proc/<pid>/fd` directory descriptors (#165, #413).
- Public eval history now retains and visibly labels partial cost and runtime evidence, distinguishes legacy `partial n/a` points from unavailable data, and supports audited source-run supersessions that activate only after an identity-compatible replacement reaches exact per-target observation parity (#427).
- Eval-history supersessions now require exact cohort identity by default and permit provenance-schema migrations only through an explicit old/new fingerprint transition that preserves every non-cohort identity check (#427).
- Eval run journals now fsync both the appended row and its containing directory, preventing an abruptly killed sandbox from losing the durable-run link while preserving fail-closed handling of torn final entries (#382).
- New public smoke sandboxes now expire after six hours and full-lane sandboxes after sixteen hours, bounding the cost of a concurrency-cancelled orphan without cutting off full EVMBench's accepted worker envelope; private workers, recovery workers, and public runs resumed from existing 24-hour launch state retain their recorded lifetime (#422; related to #371).
- Private ground-truth documents now declare a versioned target repository and immutable commit binding. Modal validates it before model work and on resume, the shared scorer revalidates it before metrics, audit-Markdown conversion preserves it, and scoring provenance records the validated subject (#423).
- Pinned local workflow-runner commands now bind the runner and its shebang interpreter to inode, size, and SHA-256 identities, invoke them through held descriptors where available, and reject replacement observed at the controller command boundary (#165).
- Event and event-index appends now repair a torn trailing JSONL fragment through size-fenced, no-follow durable mutations, preserving a complete object that lost only its newline without fusing partial evidence into the next record (#165).
- Campaign findings now own their exact single- or multi-backend provenance, and report reconciliation joins a final finding's canonical lifecycle source artifacts without a legacy failure-ID fallback; optional campaign-summary failure counts are checked against their sibling backend and finding populations. Prompt-owned report contracts require strategy detection rows and already-canonical High/Medium/Low severities, rejecting aliases instead of converting them, and omit unknown backends (#389, #390, #394, #395, #396).
- The invariant property implementation prompt now omits `reference_expectations` when none exist and reserves empty arrays for `implementation_paths` and `test_paths`, matching the artifact contract's canonical form instead of relying on legacy normalization (#328).
- Failed node attempts now retain a bounded, redacted error message beside their failure category in the durable attempt ledger, and the same safe diagnostic is included in public eval `failed_nodes`, so CI artifacts explain contract failures without Modal volume access (#361).
- The private Modal worker now corroborates its pre-raised model-work flag against model-node durable state after `eval run` returns, so reference-only and other pre-model failures use the bounded three-attempt recovery lane without relaunching ambiguous active work (#383).
- Release validation refs (`release/*` and `test/v0.1.0-ultrafuzz-bench`) now require internally consistent `scoring_ready: true` diagnostics before an operational smoke failure can use the non-default-branch hatch; feature branches keep the hatch (#370).
- Report reconciliation now discovers the recon backend on the shipped campaign node, and campaign coverage accepts only findings anchored to an observed campaign failure, so unrelated property claims cannot satisfy the failure-to-finding join (#396, #413).
- The non-default-branch smoke gate now forgives any operational failure category instead of only `resume-required` with collected diagnostics, so an infrastructure failure on one control pair no longer blocks unrelated pull requests. The failure is still surfaced as a warning annotation rather than silently passed (#321).
- Every invariant-discovery git enumeration now runs under an explicit capture bound and reports an oversized listing by naming the subcommand, the bound and the largest contributing roots, instead of failing as an anonymous `ENOBUFS` system error. Five call sites were unbounded, not the three originally reported (#323).
- A worker that ends unexpectedly now records a bounded, redacted tail of its child's stderr as the cause of its terminal error and prints a frame-only stack, so an unanticipated failure is diagnosable instead of surfacing as a bare `worker operation failed`. The public worker's previously raw stderr embedding is routed through the same redactor (#307).
- A fault the worker names itself is no longer reported as a sandbox exit, and the collector no longer demands a public eval diagnostics document that a failing build never wrote. The eval journal is now read after a nonzero `ultrafuzz eval run` exit, where the corroboration could previously never run at all; an externally killed command keeps its raised flag because it may have launched work it never journaled (#320, #332).
- `status.json` and `recovery-lifecycle.json` now render one recovery summary from a single authority, instead of independently recomputing summaries that disagreed about whether model work happened (#322).
- A verification marker the runtime refreshed can now be republished when the only difference is a digest matching the bytes actually published, instead of stranding the attempt on a byte comparison that repeated identically on every retry. Source-proof publication keeps its unconditional comparison (#280).
- A terminally failed workflow whose failing task is an artifact-preparation wrapper is preserved through worktree reaping and surfaces as an attributable failed node (#122).
- Invariant-suite source enumeration is now depth-bounded, and one shared budget is charged across the whole ancestor union before traversal rather than giving each ancestor a fresh allowance, so a deep or wide suite fails closed before roughly a thousand files are written (#218).
- Invariant-suite handoff behaviour is now covered by tests that execute the real helpers rather than harness stubs: the protected baseline outranks a rewritten sidecar, a changed `src/` helper reaches the manifest and survives one hop downstream, plural Foundry test roots are preserved, an inherited-only ancestor source survives, and an unexpected file in the suite root fails publication closed (#211, #212, #213, #214, #215).
- An invariant evidence ledger with no entries now fails both the discovery and fan-in gates unless it records `no_invariants_justification`, so silent emptiness cannot satisfy the evidence requirement while a genuinely invariant-free target stays possible and auditable. The fan-in gate also checks scan-probe containment, which it previously skipped for every ledger shape (#292).
- An absent property reference-expectation catalogue is now reported instead of silently yielding an empty identifier set, and enforcement is switchable through `[invariants] reference_expectation_enforcement`, defaulting to `warn` (#285).
- The runtime gate and the generated workflow template now share one scan-probe source validator, so `ultrafuzz validate` no longer predicts a different outcome from the run it is validating (#301).
- Recovery helpers validated against real durable state are recovered from two abandoned changes: an orphaned replacement lineage is adopted when submission reports `RUN_EXISTS`, a no-op rewind is removed from every recovery generation, strict current run-state parsing is retained, and unverified dependencies are read off the run row (#324).
- Invariant-suite handoffs now carry a deletion channel: the published manifest records tombstones, and a source a stage deleted, renamed away from, or emptied can no longer be resurrected out of an indirect ancestor artifact into a downstream workspace. A retry of the same stage drops the previous attempt's tombstones, so a source the restored workspace snapshot puts back is never published as a chain-wide deletion (#217).
- Invariant dependency handoff provenance is now persisted as a schema-validated record under durable run state and re-verified before materialization, so a restart between an invariant agent task and its verifier no longer kills the run and no longer reverts harness sources the stage already authored. The record binds itself to the ancestor manifests it was derived from, so a legitimately re-executed ancestor supersedes it instead of failing the stage closed (#219).
- A terminally failed workflow whose failing task is an artifact preparation wrapper now surfaces as a failed durable node with an `artifact-contract` failure category and a `causal_task_id` naming the wrapper, instead of leaving a ready pending node on a run that already ended; a terminal failure that still cannot be attributed to any node records a durable `WORKFLOW_TERMINAL_WITHOUT_FAILED_NODE` diagnostic naming the failing workflow tasks. A cancelled or stalled wrapper is left unattributed, and a node that later succeeds no longer keeps the failure attribution from the attempt that failed. Retry resume also reopens terminal runs that have only ready pending work, renews a stale workflow deadline without canceling an already-live backend, and makes `status` warn when terminal durable state disagrees with a live workflow runner. When synchronization observes broken workflow evidence, structured status preserves both the valid health snapshot and the original error classification in an unsuccessful envelope (#272).
- The Modal pre-model launch retry budget is now charged against consecutive attempts that never reached model work instead of every attempt a model has made in the generation, so a long run is no longer abandoned as `recovery-budget-exhausted` because earlier attempts did real model work and then asked for a durable resume. The unattended overseer now records the model-work observation it already read from the volume when it relaunches, so the streak resets on that path too, and an abandonment message names the pre-model budget only when that budget is what stopped the run. The outer no-progress recovery bound is unchanged (#267).

- Fixes durable resume hydration so it runs after the engine resets stale in-progress attempts; upgrading alone would have restored a task as finished while the durable record said pending (#274).
- A partially installed workflow-runner dependency tree now reinstalls itself instead of failing every later resume of a durable run (#274).
- `ultrafuzz doctor` now reports a posture for every workflow-engine compatibility patch instead of only the two CLI patches, and its registry check survives the upstream package rename so the upgrade signal stays alive (#274).
